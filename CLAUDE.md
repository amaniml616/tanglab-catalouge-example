# Working on this catalogue with an AI assistant

This file is instructions for Claude (or any AI coding assistant) working in this
repository. If you are a human, read `README.md` instead.

## What this repo is

A photographed inventory of the Tang Lab's optics, instruments, chemicals, wafers and
tools. 522 entries. Each has a photo, an identification, specifications, and notes on
what it does and how to use it safely.

## The one rule that matters

**`optics_catalog.csv` is the single source of truth. Edit only that.**

`index.html` and `optics_catalog_for_import.csv` are GENERATED by `build.py`. Never
hand-edit them — a GitHub Action rebuilds them on every push and will overwrite your
changes. After editing the CSV, run:

```bash
python3 build.py
```

No dependencies beyond the Python standard library. Commit the regenerated files
along with your CSV change so the site is correct even before the Action runs.

## Schema

13 columns, in this order:

| Column | Contents |
|---|---|
| `ID` | `PREFIX-NNN`, e.g. `OBJ-021`. **Never reuse or renumber an ID** — people cite them. |
| `Category` | Prefix-matched to decide the section. See the table in `build.py` (`GROUPS`). |
| `Item Name` | What it is, in plain words. Lead with the distinguishing feature. |
| `Manufacturer` | Maker, or `Unmarked` / `Not marked` if there is genuinely no marking. |
| `Part Number` | Catalogue number, serial, engraving — transcribe exactly, including lot codes. |
| `Wavelength Range` | Optical band, or `n/a` for non-optical items. |
| `Aperture / Size` | Physical dimensions, thread, mount type. |
| `Focal Length / Key Spec` | The single number that matters most for this item. |
| `Notes (Function & Operating Range)` | The substance — see below. |
| `Qty` | Integer. |
| `Loss` | **Always leave empty.** The lab fills this in by hand. |
| `Setup` | Which bench/experiment it belongs to, if known. |
| `Photo Ref` | Internal note about the source photo. Not shown on the site. |

### ID prefixes in use

`OBJ` objective · `EYE` eyepiece · `MIR` mirror · `PRI` prism · `FDM` beamsplitter/dichroic ·
`NLC` nonlinear crystal · `LSR` laser · `SAF` safety eyewear · `LED` light source ·
`MTR` meter · `DET` detector · `POL` polarizer · `WVP` waveplate · `LEN` lens ·
`STG` stage · `ACT` actuator · `CTL` controller · `CAM` camera · `FLP`/`FSP`/`FBP`/`FND` filters ·
`GRT` grating · `PIN`/`SLT` apertures · `TGT` target · `INS` instrument · `TOO` tool ·
`ACC` accessory · `MSC` unidentified · `MAJ` major instrument · `CHM` chemical ·
`WFR` wafer · `FAB` fab tool · `CLN` cleanroom supply · `ELE` electronics · `TLS` workshop tool

To add an item, take the next free number for its prefix. Check the whole file first —
do not assume the highest number is at the end.

## Writing the Notes column — this is where the value is

The notes are not descriptions. They are what a student needs in order to use the thing
without breaking it or getting a wrong answer. Aim for:

1. **What it is for, concretely, in this lab.** Cross-reference other IDs where it
   matters: "pairs with the 1830-R console (MTR-008)", "the plate equivalent is FDM-005".
2. **The one or two things that will actually bite someone.** Angle-of-incidence specs,
   polarisation dependence, damage thresholds, connector polarity (APC vs PC), hygroscopic
   crystals, cement layers that fail before the glass does.
3. **The arithmetic, when a number is needed.** Airy-disc pinhole sizing, tube-lens
   magnification scaling, GDD-induced pulse broadening. Show the formula and the result.

Write in plain sentences. Use CAPITALS sparingly, for the one warning per entry that
must not be skimmed past.

**The CSV notes field is plain text — no Markdown.** Avoid characters that break CSV
quoting; the writer handles commas and quotes, but keep line breaks out of the field.

## Honesty conventions — please preserve these

The catalogue is written to be trustworthy, which means being explicit about what is
*not* known. Two markers do the work:

- **`NOT CONFIRMED`** — anything inferred rather than read off the part or a
  manufacturer datasheet. If you looked it up and the vendor page was unreachable,
  say so.
- **`FLAG:`** — something that still needs checking, measuring, or a decision from the
  lab.

Both are collected automatically by the **Needs check** filter on the site, so open
questions stay visible instead of quietly becoming folklore.

**Do not silently upgrade a guess into a fact.** If you research an item and find the
answer, replace the flag and say what settled it. If you cannot, leave the flag.

**Do not silently merge suspected duplicates.** Add a note naming the other ID and the
test that would distinguish them, and let a human decide.

## Photos

`crops/<ID>.jpg` — the filename must equal the ID exactly. That is the entire linkage;
there is no path stored in the CSV.

Keep them small: long edge ~460 px, JPEG quality ~88, well under 200 KB. A 4 MB phone
photo makes the page slow for everyone and bloats the repo permanently, because git
keeps every version forever.

When cropping from a bench photo, crop tightly enough that the item and any readable
label fill the frame. **Verify the crop before committing** — build a contact sheet and
look at it. Mislabelled photos are worse than no photos.

## Research before writing

When identifying an item from a photo, look up the actual manufacturer specification
rather than reasoning from the form factor. Manufacturer pages for Thorlabs, Newport
and Edmund are JavaScript-rendered and often cannot be fetched directly — indexed page
titles, distributor listings, and manual PDFs usually work.

If sources disagree, say so in the notes and give the reader the test that resolves it.

## Checks before you commit

```bash
python3 build.py                      # must print the expected card count
python3 -c "import csv;r=list(csv.reader(open('optics_catalog.csv',encoding='utf-8')));\
print(len(r)-1,'rows'); assert all(len(x)==13 for x in r), 'ragged row!'"
```

Then confirm: no duplicate IDs, every new ID has a matching `crops/<ID>.jpg` (or you
deliberately left it without a photo), and `Loss` is still empty everywhere.

## Commit messages

Say what changed in the inventory, not what changed in the file:

- good: `Add Prior ProScan II controller (CTL-002); note it cannot drive the Ludl Z`
- bad: `update csv`
